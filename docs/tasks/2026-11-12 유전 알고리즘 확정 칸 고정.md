# 유전 알고리즘 튜닝 — 확정 칸 고정

## 배경

[M1 유전 알고리즘 솔버](../milestones/M1%20유전%20알고리즘%20솔버.md) 의 튜닝. 요구: 퍼즐 규칙상 반드시 정해지는 확정 칸을
계산할 수 있으면 판에 불변값으로 표시하고, 유전 알고리즘은 그 불변 칸을 인식해 변이하지 않는다.

작업 전 상태: GA 는 판에 이미 있는 칠/X 칸과 어긋나는 배치를 쓰지 않았지만(고정 칸으로 취급), 확정 칸을 스스로
계산하지는 않았다. 줄 전파는 "명백한 불가능" 검사용으로 판 복사본에서만 돌리고 결과는 버렸다.

사용자와 정한 것:

- 계산 범위 — **줄 전파를 끝까지** (행·열을 오가며 더 정할 칸이 없을 때까지). 줄 논리로 풀리는 판은 진화 없이 끝난다.
- 고정하는 칸 — **칠과 X 모두**.
- 표시 — **일반 칠/X** 로 칠한다(새 칸 상태를 만들지 않는다).

## 조사 / 원인 분석

### 단계별로 정해지는 칸 수 (번들 퍼즐)

| 퍼즐       | 줄마다 한 번 (빈 판, 교차 없음) | 줄 전파 끝까지               |
| ---------- | ------------------------------- | ---------------------------- |
| heart      | 칠 67 · X 0 (겹침 포함)         | 칠 59 · X 40 → 풀림          |
| house      | 칠 53 · X 1                     | 칠 54 · X 46 → 풀림          |
| tree       | 칠 90 · X 0                     | 칠 93 · X 132 → 풀림         |
| cup        | 칠 62 · X 12                    | 칠 96 · X 129 → 풀림         |
| random-30  | 칠 130 · X 0                    | 칠 536 · X 364 → 풀림        |
| random-20  | 칠 23 · X 0                     | 칠 55 · X 28 (83/400) 멈춤   |
| 석상 40×40 | 칠 62 · X 0                     | 칠 88 · X 80 (168/1600) 멈춤 |

### 예전 변이가 고정 칸에서 헛돈다

예전 변이는 "틈 둘을 무작위로 골라 빈칸을 옮겨 보고, 고정 칸과 어긋나면 되돌리기를 8번까지 → 다 실패하면 줄을 통째로
다시 뽑기" 였다. 고정 칸이 많아지면 실패가 늘어난다(변이 10만 번 측정):

| 판                  | 고정 칸 | 다시 뽑기로 빠진 비율 | 변이당 시도 |
| ------------------- | ------- | --------------------- | ----------- |
| random-20           | 0       | 3.7%                  | 0.96        |
| random-20 (줄 전파) | 83      | **19.6%**             | 1.71        |
| 석상 (줄 전파)      | 168     | 0.8%                  | 1.32        |

줄을 다시 뽑는 것은 큰 점프라, 특히 다듬기(작은 이동을 쌓아 가는 지역 탐색)에서 손해다.

### 고정 칸과 맞는 이동만 나열하기

틈 a 의 빈칸 하나를 틈 b 로 옮기면 그 사이 조각들이 한 칸씩 밀린다. 조각 하나가 밀릴 때 바뀌는 칸은 둘(새로 칠해지는 칸,
새로 비는 칸)뿐이므로 그 두 칸만 고정 칸과 맞춰 보면 된다. b 를 a 에서 가까운 쪽부터 넓혀 가다 한 조각이 막히면 그 너머는
모두 막힌다 → 조기 종료. 유전자는 늘 고정 칸과 맞는 상태라는 불변식(초기화·교차·변이·다시 뽑기가 모두 지킨다) 위에서
성립한다. "해 보고 `gapsFit` 로 검사" 와 무작위 2만 건에서 결과가 같았다.

## 변경 사항

- `src/lib/solver/genetic.ts`
  - `gapMoves(gaps, gOff, clue, fixed, starts, out)` — 고정 칸과 맞는 빈칸 옮기기를 모두 나열(위 방법).
  - `#mutateLine` — 맞는 이동 가운데 하나를 고르게 뽑는다. 그런 이동이 없거나 15%(`resampleRate`) 확률이면 고정 칸과 맞는
    배치 가운데서 고르게 다시 뽑는다. 해 보고 되돌리는 시도는 없앴다.
  - `GeneticSearch.population` (읽기 전용) — 시험에서 모든 개체를 검사하려고.
- `src/lib/solver/strategies/genetic.ts`
  - **0 단계 확정 칸**: 단서 합 검사 뒤 실제 판에서 `propagate` 를 끝까지 돌려 확정 칸을 칠/X 로 칠한다(기록 `(확정) R3: 칠 2 · X 1`).
    끝나면 `확정 칸 83/400 (줄 전파로 +83) — 진화는 남은 317칸만 찾는다`. 모순이면 `풀 수 없는 퍼즐 — 줄 전파 중 R2 에서 모순`,
    다 풀리면 `줄 전파만으로 풀렸다 — 진화가 필요 없다` 로 끝낸다.
  - 그 뒤 스캔(경우의 수는 확정 칸 반영) → 축 고르기 → 진화는 그대로. 확정 칸은 `fixedMask` 로 고정되어 배치·변이·교차·다듬기에서
    바뀌지 않고, 후보 그리기도 칠/X 칸은 건너뛴다.
  - 옵션 `fixCells`(기본 true). false 면 예전처럼 판에 있는 칸만 지키고, 불가능 검사는 판 복사본 줄 전파로(비교·시험용).
  - 줄 전파 중 마지막으로 비춘 줄을 기억하는 `trackLine` (모순 난 줄 이름).
  - 전략 설명에 "먼저 줄 전파로 반드시 칠/X 인 칸을 칠해 두고(진화 중 불변)" 추가.
- `src/lib/solver/genetic.spec.ts` — 시험 7개 추가, 9개 고침 (아래 검증)
- `scripts/bench-genetic.ts` — 기본으로 줄 전파 확정 칸을 고정하고 시작, `--no-fix` 로 끔(예전 `--pre` 를 뒤집음). 줄 전파로 풀리면 "줄 전파로 풀림".
- `docs/milestones/M1 유전 알고리즘 솔버.md` — 튜닝 1 요구·설계(0 단계, 변이)·완료 조건·측정 추가. 처음 구현의 측정 표는 그대로 둠.

## 남은 고려사항

- 줄 논리로 풀리는 판(번들 7개 중 5개)에서는 GA 가 돌지 않는다. GA 자체를 보려면 콘솔에서 `nono.run(nono.genetic({ fixCells: false }))`.
- 확정 칸은 일반 칠/X 라서, 일시정지 중 사람이 고칠 수 있다. 진화 모델은 시작할 때의 판으로 만들어지므로 그 변경은 반영되지 않는다(후보 그리기는 칠/X 칸을 건너뛴다).
- 줄 전파 모순으로 오류가 나면 그때까지 칠한 확정 칸이 판에 남는다(예전엔 판 복사본에서 검사해 판이 깨끗했다). 되돌리기 한 번으로 실행 전체가 돌아간다.
- 40×40 석상은 여전히 못 푼다. 다음 후보는 가정 & 모순으로 더 많은 칸을 고정(232칸)한 뒤 진화, 다양성 유지, 유도 변이.
- 아무것도 커밋하지 않았다.
