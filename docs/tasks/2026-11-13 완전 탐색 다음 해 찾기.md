# 완전 탐색 튜닝 — 해마다 멈추고 다음 해 찾기

## 배경

[완전 탐색 솔버](2026-11-13%20완전%20탐색%20솔버.md) 의 첫 구현은 해 1 을 찾으면 확정하고, 판을 그대로 둔 채 해 2 가
있는지만 조용히 확인한 뒤 끝났다(기본 해 수 한도 2). 사용자 요청: 해가 여럿이면 다음 해를 찾아 계속 탐색할 수 있게.

## 조사 / 원인 분석

- 전략이 실행기를 멈추게 할 방법이 없었다. 단계 종류는 `inspect`·`paint`·`memo-clear`·`memo-commit`·`note` 뿐이고,
  일시정지는 사용자(버튼)만 할 수 있었다.
- 해 1 을 `memoCommit` 으로 확정하면, 그 칸은 이후 탐색이 그리는 메모 차이에서 "손대지 않는 확정 칸" 과 구별되지
  않았다. 다음 해를 그리려면 공통 칸(주어진 칸 + 줄 전파 + 뿌리 탐침)과 해로 보여 준 칸을 따로 알아야 한다.
- 판의 "완성" 은 판 상태에서 바로 나오는 값(`game.solved` = 모든 줄이 맞고 메모 0)이다. 해를 칠/X 로 보였다가 다시
  메모로 돌려도 부작용(타이머·기록 등)이 없다.

## 변경 사항

- `src/lib/solver/types.ts` — 새 단계 `{ kind: 'pause'; note? }`: 판은 그대로, 실행기에 일시정지를 청한다.
  headless 실행기는 무시한다.
- `src/lib/solver/steps.ts` — `pause(note?)` 도우미. `src/lib/solver/apply.ts` — `pause` 는 판을 바꾸지 않는
  (idle) 단계.
- `src/lib/game/runner.svelte.ts` — `pause` 단계를 적용하면 스스로 `pause()` 하고 그 박자의 남은 몫을 버린다.
  계속(▶)하면 다음 단계부터 이어 간다. 한 단계 버튼으로 진행할 때도 그 자리에서 끊는다.
- `src/lib/solver/strategies/backtracking.ts`
  - 해 수 한도 기본값 2 → **없음**(`maxSolutions` 를 주면 그만큼).
  - 해를 찾으면 칠/X 로 보여 준다(판이 "완성"). 기록 `해 k — 모든 줄이 단서와 맞는다 · 앞 해와 n칸이 다르다: (x,y) …`
    를 남긴 뒤 `pause`(`해 k 에서 멈춤 — 계속하면 남은 가지에서 다음 해를 찾는다`) 를 낸다.
  - 계속하면 다음 가정 단계가 해로 보였던 칸을 다시 메모로 돌리고 남은 가지를 탐색한다. 공통 칸은 `fixed` 표시로
    따로 두어 건드리지 않는다.
  - 멈추지 않는 경우: 가정 없이 풀린 판(그 해가 유일해), 한도에 닿은 해(탐색이 곧 끝남), `pauseOnSolution: false`.
  - 가지를 다 보면 마지막에 찾은 해를 판에 남긴다. 결과 문구는 `유일해 — …` / `해가 여럿 — 해 N개를 모두 찾았다. 판은 해 N`
    / `해가 여럿 — 한도(M)까지 해 N개를 찾았다. 판은 해 N` / `해 없음 — …`. 해를 보여 주는 중에 정지하면
    그 해가 판에 남는다(결과 `stopped`).
  - 새 옵션 `pauseOnSolution`(기본 true).
- `src/lib/game/session.svelte.ts` — 콘솔 `nono.steps.pause`.
- `src/lib/components/SolverPanel.svelte` — 기록에서 `pause` 줄을 메모 확정·지우기처럼 강조.
- 시험
  - `runner.spec.ts`: `pause` 단계에서 한 박자에 10단계를 줘도 끊고 일시정지, 계속하면 이어 감 / 2×2 대각선을 완전
    탐색 → 해 1 에서 멈춤(완성) → 계속 → 다른 해 2 에서 멈춤 → 계속 → 끝, 판은 해 2, 되돌리기 한 번에 처음 판.
  - `backtrack.spec.ts`: 해마다 멈출 때 판이 메모 없는 해이고 서로 다름, 끝난 판은 마지막 해 / 무작위 5×5 판(해 4~30개)에서
    멈춤 수 = 서로 다른 해 수 = 전수 탐색 수 / `pauseOnSolution: false` · 한도 2 일 때 멈춤 1번 / 가정 없이 풀린 판은
    멈추지 않음. 석상·도중 정지 시험은 `maxSolutions: 2` 로(한도가 없으면 석상은 해가 10만 개 넘게 이어진다).

## 검증

- 단위 시험 `bunx vitest run --project server`: **9 파일 100개 통과**. `svelte-check` 오류 0(경고 1은 기존
  `worker-configuration.d.ts`), `eslint src scripts` 0, `prettier --check src scripts docs/tasks` 통과.
- 브라우저(Windows Chrome 157, CDP, 사용자가 띄운 dev 서버 5173), 석상, 최고 속도:
  - 실행 → 약 7.6초 뒤 해 1 에서 일시정지, "완성" 표시, 버튼 "계속", 메모 0.
  - 계속 → 29ms 뒤 해 2 에서 멈춤, 앞 해와 4칸 다름 `(33,9) (35,9) (33,14) (35,14)`.
  - 계속 → 56ms 뒤 해 3 에서 멈춤, 앞 해와 8칸 다름 `(6,3) (7,3) (6,7) (7,7) (33,9) (35,9) (33,14) (35,14)`.
  - 정지 → 결과 `stopped`, 해 3 이 판에 남음("완성"). 되돌리기 한 번에 빈 판. 콘솔 오류 0.
  - 브라우저 확인 뒤 기록 문구의 조사를 고쳤다("해 2 과" → "앞 해와"). 이 문구는 단위 시험으로만 확인했다.
- 확인 중 한 번, dev 서버가 수정 도중의 `session.svelte.ts` 변환본(`pause` import 가 빠진 것)을 내보내
  `ReferenceError: pause is not defined` 가 났다. 디스크의 파일은 맞았고 타입 검사도 통과했다. 파일 시각을 갱신(`touch`)하자
  다시 변환되어 사라졌다. 열려 있던 탭에서 같은 오류가 보이면 새로 고치면 된다.

## 남은 고려사항

- 한도가 기본으로 없으므로 headless(`nono.headless('backtracking')`, `runHeadless`)로 해가 아주 많은 판을 돌리면
  실행기 단계 한도(5,000,000)까지 이어진다. 화면 실행은 해마다 멈추므로 문제없다. headless 로 셀 때는
  `createBacktracking({ maxSolutions: n })` 이나 `scripts/count-solutions.ts` 를 쓴다.
- 해 사이의 차이는 기록에만 적는다(판에서 다른 칸을 따로 표시하지는 않는다).
- 석상처럼 해가 아주 많은 판에서는 깊이 우선 순서대로 비슷한 해가 이어진다. 많이 다른 해를 먼저 보는 것은 하지 않았다.
- 아무것도 커밋하지 않았다.
