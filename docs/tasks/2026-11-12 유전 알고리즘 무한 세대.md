# 유전 알고리즘 튜닝 2 — 무한 세대·돌연변이 확률

## 배경

[M1 유전 알고리즘 솔버](../milestones/M1%20유전%20알고리즘%20솔버.md) 의 두 번째 튜닝. 샘플(40×40 석상)을 여전히 못 푸는데
답이 없는 문제는 아닐 것이므로:

- 세대 한도에서 포기하는 로직을 없애고 무한히 세대를 이어 간다. (말씀은 6,000세대였지만 코드의 한도는 `DEFAULT_MAX_GENERATIONS = 5000`)
- 돌연변이 확률을 좀 높인다.
- (작업 중 추가) 되돌리기 스택 한도값은 1000. — 코드의 기본값은 200 이었다.

## 조사 / 원인 분석

### 무한 진화는 되돌리기 기록을 끝없이 키운다

화면 실행기는 실행 하나를 되돌리기 한 번으로 돌리려고 모든 변경을 같은 이름(`historyTag`)의 기록 하나에 덧붙인다.
진화는 세대마다 후보 메모를 다시 그리므로 이 기록이 계속 커진다. 측정(500세대): 40×40 은 세대당 35.9건(세대당 19.4ms),
20×20 은 7.5건. 한 시간이면 40×40 에서 약 650만 건이다.

되돌리기 한도(기록 개수)는 이것을 막지 못한다 — 실행 하나가 기록 하나라서. 그래서 묶음 기록 안에서는 칸마다
"처음 값 → 마지막 값" 하나로 합친다. 되돌리기는 실행 전 값으로 돌려놓기만 하면 되므로 결과가 같고, 기록은 칸 수
이상 커지지 않는다. 바뀌었다 제자리로 돌아온 칸은 되돌리기·다시 하기 때 내보내지 않는다.

### 돌연변이 확률

줄마다 변이할 확률(`mutationRate`, 자식마다 적어도 한 줄은 변이)을 비교했다. 줄 전파 확정 칸 고정, 다른 값은 기본.

| 확률 | random-20 (씨앗 20, 6,000세대 한도) | 석상 1,000세대 불일치 (씨앗 4) |
| ---- | ----------------------------------- | ------------------------------ |
| 0.05 | 20/20 · 중앙값 765 · 최대 2,123세대 | 42·48·50·56                    |
| 0.1  | 20/20 · 중앙값 420 · 최대 5,686세대 | 60·60·62·62                    |
| 0.15 | 20/20 · 중앙값 694 · 최대 3,873세대 | 56·60·62·62                    |
| 0.2  | 20/20 · 중앙값 864 · 최대 5,053세대 | 54·58·60·60                    |

1,000세대만 보면 확률을 올릴수록 석상이 나빠 보이지만, 무한 진화에서는 오래 볼 때가 중요하다. 석상을 5,000세대까지
본 결과(1,000세대마다 지금까지 최선):

| 확률 | 씨앗 1             | 씨앗 2             | 씨앗 3             |
| ---- | ------------------ | ------------------ | ------------------ |
| 0.05 | 48 48 48 48 48     | 56 50 50 50 50     | 42 42 42 42 42     |
| 0.1  | 62 56 56 50 **50** | 60 54 54 50 **44** | 60 58 58 56 **56** |

0.05 는 1,000~2,000세대에 굳고 그 뒤로는 재시작해도 기록을 넘지 못한다. 0.1 은 느리게 시작하지만 계속 내려간다 →
**0.1** 로 정했다. 20×20 도 중앙값이 765 → 420세대로 줄었다(최대는 늘었다).

### 0.1 로 20,000세대 — 석상은 바닥에 닿는다

| 씨앗 | 최선 (1,000세대마다)                                       | 재시작 |
| ---- | ---------------------------------------------------------- | ------ |
| 1    | 62 56 56 50 50 50 50 **42** (8,000세대) 이후 20,000까지 42 | 22     |
| 2    | 60 54 54 50 **44** (5,000세대) 이후 20,000까지 44          | 25     |
| 3    | 60 58 58 56 56 42 **40** (7,000세대) 이후 20,000까지 40    | 26     |

세대 한도를 없애도 석상은 불일치 40 근처에서 멈춘다. 재시작한 개체군은 매번 다른 지역 최적(대개 40~60)으로 가고,
지금까지 최선을 넘지 못한다. 무한 진화만으로는 풀릴 가능성이 낮다 — 다음 후보는 마일스톤 문서의 "다음 후보".

## 변경 사항

- `src/lib/solver/strategies/genetic.ts`
  - `maxGenerations` 옵션과 `DEFAULT_MAX_GENERATIONS`(5000), 한도에 닿으면 메모를 지우고 `stalled` 로 끝내던 분기를 없앴다.
    불일치 0 이 되거나 실행기가 멈출 때까지(정지 버튼, headless 의 `maxSteps`) 진화한다.
  - 전략 설명에 "그때까지 세대 한도 없이 이어 간다(정지 버튼으로 멈춘다)".
- `src/lib/solver/genetic.ts` — 기본 `mutationRate` 0.05 → **0.1**.
- `src/lib/nonogram/board.ts`
  - 기본 `historyLimit` 200 → **1000**.
  - 묶음(`historyTag`) 기록은 칸 → 위치 맵(`slots`)을 두고 같은 칸의 변경을 하나로 합친다(`#mergeInto`). 처음 from 은 두고 to 만 바꾼다.
  - 되돌리기·다시 하기는 from = to 인(바뀌었다 돌아온) 칸을 건너뛰고 내보내지 않는다.
- 시험
  - `board.spec.ts`: 같은 칸들을 1,000번 다시 그린 묶음 → 되돌리기는 실제로 바뀐 두 칸만 실행 전 값으로, 다시 하기도 두 칸 / 되돌리기 한도 1000.
  - `genetic.spec.ts`: 세대 한도 시험 두 개를 바꿨다 — 해 없는 4×4 가 예전 한도를 넘어 6,500세대 기록을 남기고 실행기의 7,000단계 한도에서야 멈춘다 /
    random-20 을 도중에 멈추면 확정 칸은 줄 전파 결과 그대로, 나머지 칸은 후보 메모로 남는다.
- `docs/milestones/M1 유전 알고리즘 솔버.md` — 튜닝 2 요구·설계·완료 조건·측정.

`scripts/bench-genetic.ts` 의 `최대 세대` 인자는 측정용이라 그대로 두었다(전략과 무관).

## 남은 고려사항

- 해가 없는 판(줄 전파로 안 드러나는 경우)도 이제 스스로 끝나지 않는다 — 정지 버튼으로 멈춰야 한다.
- 실행 중 기록은 합쳐지지만, 실행기 화면 기록(솔버 패널 목록)은 원래대로 최근 300개만 보인다.
- 실행 묶음 기록을 합치는 것은 Board 의 일반 규칙이라 다른 솔버의 실행 묶음에도 적용된다(되돌리기 결과는 같다).
- 석상은 20,000세대에서도 불일치 40~44 에서 멈췄다(위). 세대 한도를 없앤 것만으로는 부족하다.
- 돌연변이 확률 0.1 은 20×20 의 오래 걸리는 꼬리를 늘렸다(최대 2,123 → 5,686세대). 무한 진화에서 끝내 풀리느냐가 더 중요하다고 보고 정했다.
- 아무것도 커밋하지 않았다.
