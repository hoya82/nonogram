# 노노그램 게임판 재구현과 솔버 실행 구조

## 배경

nemonemologic.com 의 노노그램 게임판을 SvelteKit(+adapter-cloudflare)으로 재구현한다. 사이트 클론이 아니라
게임 자체가 목적이며, 최종 목표는 **자동 풀이 기계(솔버) 설계**다. 요구 사항:

- `docs/references/board.html` 을 분석해 `{header:{version:1}, rows:[[34],…], cols:[[7,19],…]}` 모양의 단서 자료구조를 만든다.
- 참고 CSS·JS 의 게임판 동작을 핵심 기능만 골라 SvelteKit 답게 재구성하고, 복잡한 이벤트 처리는 RxJS 로.
- 노노그램의 구성 규칙을 TypeScript 타입·검증에 반영한다.
- 함수 호출로 판 상태를 쉽게 바꿀 수 있고, 그 변화가 **틱(프레임) 단위 애니메이션**으로 보여야 한다.
- 솔버 전략을 여러 개 쓸 수 있는 추상화.

### 40×40 참고 퍼즐(나 혼자만 레벨업 석상)의 성질

- 추출한 단서는 스크린샷과 일치(행1 `34`, 열1 `7 19`, 열2 `1 2 3 1` …). 행 단서 40개 모두 회문, 열 단서는 좌우 대칭 — 그림이 좌우 대칭.
- **이 판은 매우 어렵다**: 줄 전파 168/1600칸, 가정 & 모순(1칸 가정 + 양쪽 공통) 232/1600칸에서 멈춤.
  가장 제약 많은 칸부터 고르는 DFS(전파 포함)로 391,476 노드·150초를 돌려도 해를 하나도 찾지 못했다.
  해가 여럿일 가능성도 있다(사이트는 정답 md5 하나와 비교하므로 유일해를 보장하지 않는다).
  → 지금은 "강한 솔버를 시험할 어려운 기준 판" 으로 두었다.
- 줄 풀이 DP 의 정확성은 따로 확인했다: 무작위 줄 2만 개(+시험 3천 개)를 모든 칠하기 나열과 비교해 불일치 0.

## 변경 사항

### 의존성

- `rxjs@^7.8.2` 추가 (dependencies).

### 도메인 코어 — 프레임워크 무관 순수 TS (`src/lib/nonogram/`)

- `cell.ts` — `Cell` 값(사이트와 같은 0~4)과 술어(`isFilled`/`isCrossed`/`isMemo` …).
- `puzzle.ts` — `Run`(1 이상 정수 브랜드 타입)·`LineClue`·`Puzzle`, 파일 포맷 `PuzzleFileV1`.
  `createPuzzle`/`parsePuzzleFile` 이 구성 규칙(숫자 ≥1, 빈 줄은 `[0]`, 줄 최소 길이 ≤ 줄 길이, 행 합 = 열 합)을 검사해 `Result` 로 돌려준다.
- `line.ts` — `LineRef`, `isLineSatisfied`, **`analyzeLine`(O(n·m) 줄 DP: 칸별 칠/비움 가능성, 숫자별 시작 가능 칸)**,
  `solveLine`(완전 줄 풀이), `overlapLine`(좌우 극단 겹치기), `settledClues`(끝난 숫자 지우기).
- `board.ts` — `Board`: 칸 저장소(`CellStore`)를 바꿔 끼우는 게임 규칙 모델. 칠하기·자동 X·메모·되돌리기(태그로 묶기)·`events$`(RxJS Subject).
- `formats/nemonemo.ts` — board.html / 사이트 `puzzleData({hhints,vhints})` / v1 JSON 을 읽는 파서(정규식, DOM 없음).
- `formats/picture.ts` — 그림 → 단서 (예제·시험용).

### 솔버 (`src/lib/solver/`)

- `types.ts` — **전략 = 제너레이터**. 판을 직접 바꾸지 않고 `SolverStep`(`inspect`/`paint`/`memo-clear`/`memo-commit`/`note`)을 yield 하면
  실행기가 적용한 뒤 다음 `next()` 를 부른다 → yield 뒤엔 판이 늘 최신, 박자는 실행기가 정함, `yield*` 로 합성.
- `propagate.ts` — 공용 하위 절차: 중복 없는 줄 대기열 + 줄 풀이 함수 교체 가능(`lineSolver`) + 메모 모드 + 끝에 전체 재훑기(자동 X·사람 손질 반영).
- `strategies/` — 예제 전략 4개, 각자 다른 모양의 추상화 사용 예:
  - `overlap-sweep` 겹치기 훑기 (고정 순서 훑기, 약한 기준선)
  - `line-propagation` 줄 전파 (`yield* propagate`)
  - `overlap-then-propagation` (같은 전파 절차에 줄 풀이 함수 바꿔 끼우기)
  - `probing` 가정 & 모순 (메모로 가정 → 메모 전파 → 모순이면 반대로 확정 / 양쪽 공통 칸 확정 / 다 맞으면 메모 확정)
- `apply.ts`, `headless.ts` — 화면 없이 끝까지 돌리는 실행기(시험·벤치마크). 화면과 같은 `Board` 규칙을 쓴다.
- `index.ts` — 공개 API 와 `STRATEGIES` 목록 (새 전략은 여기에 넣으면 화면에 나온다).

### 화면 상태·입력 (`src/lib/game/`)

- `game.svelte.ts` — `ReactiveCellStore`($state 배열: 칸마다 따로 반응), 줄마다 `LineStatus`($derived: 완성·모순·끝난 숫자 — 그 줄의 칸이 바뀔 때만 재계산),
  되돌리기 가능 여부는 `board.events$` 를 `createSubscriber` 로 연결.
- `runner.svelte.ts` — **솔버 실행기**. `combineLatest(playing$, pace$) → switchMap(clock)` + `manual$`(한 단계) → `takeUntil(stop$)`.
  박자: 초당 N 단계(프레임에 맞춰 쌓아 냄)·프레임당 N 단계·최고 속도(프레임마다 12ms 시간 분할). 단위: 줄(단계) / 칸(칠하기를 칸 하나씩).
  실행 하나는 되돌리기 한 번으로 돌아간다(history tag). 시험용 가짜 박자(`clock`) 주입 가능.
- `stroke.ts` — 획 계산(순수 함수): 누른 칸으로 모드 결정, 축 고정, 사각형 모드, 메모 획은 빈칸·메모 칸만.
- `input.ts` — RxJS 입력 파이프라인을 attachment 로: 포인터 획(`exhaustMap` 으로 두 번째 포인터 무시, `scan` 으로 획 상태, `race(pointerup, Escape)` 로 확정/취소,
  `auditTime(animationFrameScheduler)`), 가이드 줄, 이동 도구·가운데 버튼 끌기, Ctrl+휠 확대(`throttleTime`), 단축키, 스페이스 누르는 동안 이동(창 blur 시 해제).
- `settings.svelte.ts` — 설정(localStorage, 실패해도 기본값으로 동작), `session.svelte.ts` — 세션·명령·콘솔 API(`window.nono`).

### 컴포넌트·라우트

## 남은 고려사항

- **40×40 참고 판은 아직 아무 전략으로도 못 푼다.** 다음 후보: 두 칸 가정(2-probing), 줄 단위 가정, 전파 포함 백트래킹 전략(메모로 가지를 그리고 되감기),
  해 개수 세기로 유일해 여부부터 확인.
- 진행 저장 없음 — 새로고침하면 판이 처음으로 돌아간다(설정만 저장).
- 전략이 직접 하지 않은 변화(자동 X, 일시정지 중 사람이 고친 칸)는 `propagate` 끝의 전체 재훑기로 반영한다. 새 전략이 `propagate` 를 쓰지 않으면 같은 처리가 필요하다.
- 솔버가 판을 바꾸는 동안 사람이 칠하면 되돌리기 기록이 솔버 묶음 사이에 끼어든다(LIFO 는 유지됨).
- 아무것도 커밋하지 않았다.

### 새 전략 만들기 (요약)

```ts
// src/lib/solver/strategies/my-strategy.ts
export const myStrategy = defineStrategy({
	id: 'my-strategy',
	name: '내 전략',
	description: '…',
	*solve(ctx) {
		// ctx.board 는 yield 뒤마다 최신. 판은 단계를 yield 해서만 바꾼다
		const r = yield* propagate(ctx, { lineSolver: myLineSolver });
		if (r === 'contradiction') return { status: 'contradiction' };
		yield paint([{ x: 0, y: 0, value: Cell.Filled }], rowRef(0), '근거');
		return finalOutcome(ctx);
	}
});
// src/lib/solver/index.ts 의 STRATEGIES 에 추가 → 화면 선택 목록·nono.run('my-strategy')·runHeadless 에서 바로 쓴다
```
