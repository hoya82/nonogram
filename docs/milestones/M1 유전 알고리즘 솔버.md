## 목표

지금까지의 솔버(겹치기·줄 전파·가정 & 모순)는 모두 **줄 논리** 계열이다. 이 마일스톤은 전혀 다른 계열인
**확률적 탐색 솔버** — 유전 알고리즘(GA) — 를 기존 전략 추상화(제너레이터 + 단계 yield) 위에 하나 더 얹는다.
요구 사항:

1. 행과 열을 스캔한다.
2. 행과 열 중 경우의 수가 더 적은 쪽을 고른다.
3. 빈칸(건너뛰기)의 삽입을 유전자로, 반대 축의 불일치도를 평가 함수로 하는 유전 알고리즘을 작성한다.
4. 불일치도가 0 이 되면 퍼즐이 풀린 것이다.
5. 불가능한 퍼즐임이 명백하면 오류를 내고 끝낸다.

**튜닝 1** (같은 날 추가): 퍼즐 규칙상 반드시 정해지는 확정 칸을 계산할 수 있으면 판에 불변값으로 표시하고,
유전 알고리즘은 그 불변 칸을 인식해 변이하지 않는다. 정한 것 — 계산 범위는 **줄 전파를 끝까지**, 고정하는 칸은
**칠과 X 모두**, 표시는 **일반 칠/X** (새 칸 상태를 만들지 않는다).

**튜닝 2** (같은 날 추가): 세대 한도(5,000)에서 포기하는 로직을 없애고 풀릴 때까지 세대를 이어 간다. 돌연변이 확률을
올린다(줄마다 0.05 → 0.1). 되돌리기 기록 한도는 1000.

## 설계 — 요구와 구현의 대응

| 요구                    | 구현                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| ----------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 0. 확정 칸 (튜닝 1)     | 진화 전에 실제 판에서 줄 전파를 끝까지 돌려(`(확정) R3: 칠 2` 처럼 기록) 반드시 칠/X 인 칸을 일반 칠/X 로 칠한다. 이 칸은 진화 내내 불변: 주 축 줄의 배치는 고정 칸과 맞는 것만 쓰고, 변이·교차·다듬기·후보 그리기 모두 건드리지 않는다. 줄 전파만으로 풀리면 진화 없이 끝난다. `fixCells: false` 면 이 단계를 건너뛴다(비교·시험용).                                                                                                                                                               |
| 1. 행·열 스캔           | 모든 줄을 `inspect` 단계로 비추며(파란 테두리) 그 줄의 **경우의 수**를 기록한다. 경우의 수 = 판에 이미 확정된 칸(칠/X)과 어긋나지 않는 배치 수. 줄 DP 로 정확히 센다(`countPlacements`).                                                                                                                                                                                                                                                                                                            |
| 2. 경우의 수 적은 축    | 축의 경우의 수 = 줄별 경우의 수의 곱(로그 합으로 비교). 작은 쪽이 **주 축(유전자 축)**, 같으면 행.                                                                                                                                                                                                                                                                                                                                                                                                  |
| 3. 유전자               | 주 축 줄마다 `e[0..m]` = 틈마다 넣은 **여분 빈칸 수**(첫 조각 앞 / 조각 사이 필수 빈칸 뒤 / 끝). Σe = 줄의 여유. 그래서 주 축 줄은 언제나 자기 단서를 만족한다. 빈칸 하나를 다른 틈으로 옮기면 그 사이 조각들이 한 칸씩 움직인다.                                                                                                                                                                                                                                                                   |
| 3. 평가 함수            | **불일치도** = 반대 축 줄마다 "단서를 만족시키려면 최소 몇 칸을 뒤집어야 하나"(줄 거리 DP, O(n·m))의 합. 작을수록 좋다.                                                                                                                                                                                                                                                                                                                                                                             |
| 3. 진화 연산            | 토너먼트 선택(3) · 두 점 교차(이어진 주 축 줄 묶음을 바꿈) · 변이(줄마다 확률 0.1, 자식마다 적어도 한 줄 — 튜닝 2 에서 0.05 → 0.1. 빈칸 하나를 다른 틈으로 — **고정 칸과 맞는 이동만 모두 나열해 그중 하나**(`gapMoves`), 그런 이동이 없거나 15% 확률로 줄을 고정 칸과 맞는 배치 가운데서 고르게 다시 뽑음) · 엘리트 2 · **정체 300세대면 개체군을 통째로 새로 뿌림** · **다듬기**: 세대마다 최선 개체에 변이 800번, 불일치도가 나빠지지 않으면 받아들임(메메틱 GA, 바뀐 열만 다시 재는 증분 평가). |
| 4. 불일치도 0           | 그 개체가 해다. 진화 중 메모(주황)로 그려 둔 후보를 **메모 확정** → `solved`. 튜닝 2 부터 **세대 한도 없음** — 불일치 0 이 되거나 실행기가 멈출 때까지(정지 버튼, headless 의 `maxSteps`) 진화한다.                                                                                                                                                                                                                                                                                                 |
| 5. 명백한 불가능 → 오류 | 셋 다 "해가 없다" 는 증명이다: ① 행 단서 합 ≠ 열 단서 합 ② 줄 전파가 모순(튜닝 1 부터는 0 단계의 줄 전파가 잡는다. `fixCells: false` 면 판 복사본에서 검사) ③ 판의 확정 칸 때문에 배치가 0 인 줄(스캔). → `{ status: 'error', note: '풀 수 없는 퍼즐 — …' }`. 줄 전파로도 드러나지 않는 불가능은 GA 로 증명할 수 없다 — 튜닝 2 부터는 끝나지 않고 정지할 때까지 진화한다(처음 구현은 5,000세대에서 `stalled`).                                                                                      |

화면에서는 세대마다 **지금 개체군의 최선 개체**를 주황 메모(▲ 칠 / `/` 비움)로 그린다. 반대 축 줄의 빨간 모순 표시가
곧 그 세대의 불일치 줄이다. 세대마다 단계를 하나씩 yield 하므로 박자(초당 N 단계·프레임당 N 단계·최고 속도)가
그대로 "초당 N 세대" 가 되고, 실행 하나는 되돌리기 한 번으로 돌아간다. 튜닝 2 부터 실행 묶음 기록은 칸마다 "처음 값 →
마지막 값" 하나로 합쳐 두므로, 끝없이 돌아도 기록이 칸 수 이상 커지지 않는다(전엔 40×40 에서 세대당 약 36건씩 쌓였다).

### 튜닝 2 — 돌연변이 확률 (줄 전파 확정 칸 고정 상태)

| 줄당 확률  | random-20 (씨앗 20)                 | 석상 1,000세대 불일치 | 석상 지금까지 최선, 1,000세대마다 (씨앗 1·2·3)               |
| ---------- | ----------------------------------- | --------------------- | ------------------------------------------------------------ |
| 0.05       | 20/20 · 중앙값 765 · 최대 2,123세대 | 42·48·50·56           | 48→48→48→48→48 · 56→50→50→50→50 · 42→42→42→42→42 (5,000세대) |
| **0.1**    | 20/20 · 중앙값 420 · 최대 5,686세대 | 60·60·62·62           | 62→56→56→50→50 · 60→54→54→50→44 · 60→58→58→56→56 (5,000세대) |
| 0.15 · 0.2 | 20/20 · 중앙값 694 · 864세대        | 56–62 · 54–60         | —                                                            |

- 0.05 는 1,000~2,000세대에 굳고, 0.1 은 5,000세대까지 계속 내려가서 0.1 로 정했다.
- **0.1 로 20,000세대**(세대당 약 20ms, 7분): 최선 불일치 42·44·40. 셋 다 5,000~8,000세대에 바닥에 닿은 뒤 남은
  12,000세대 이상, 재시작 22~26번 동안 기록을 넘지 못했다. 무한 진화만으로 석상이 풀릴 가능성은 낮아 보인다.

### 튜닝 1 — 확정 칸 고정 + 고정 칸을 아는 변이

| 예제 4개·30×30      | (아래 표와 같음)                                     | 줄 전파만으로 풀림 — 진화 없음                                              |
| random-20 (씨앗 30) | 30/30 · 중앙값 791세대·4.4초 · 최대 5,201세대·29.1초 | 30/30 · 중앙값 790세대·3.8초 · **최대 2,887세대·12.9초**                    |
| 석상 40×40 (씨앗 4) | 1,000세대에서 불일치 68·68·70·78                     | 1,000세대에서 불일치 **42·48·50·56** (168칸 고정, 공간 10^201.9 → 10^176.3) |

- 고정 칸이 있을 때 예전 변이(무작위로 옮겨 보고 8번까지 되돌림)는 20×20 에서 변이의 19.6% 가 "옮기기 실패 → 줄
  통째로 다시 뽑기" 로 빠졌다(작은 이동이 큰 점프가 된다). 새 변이는 맞는 이동만 나열하므로 헛시도가 없다.
- random-20 은 중앙값이 그대로지만 오래 걸리는 꼬리가 절반 이하로 줄었다. 40×40 은 아직 못 풀지만 같은 세대에서
  불일치가 확실히 낮다.
- 브라우저(Chrome, 최고 속도)에서 random-20: 83칸 고정 → 1,479세대에 풀림, 확정 칸 중 바뀐 칸 0.

- 진화를 웹 워커로 옮겨 최고 속도에서도 화면 프레임을 지키기.
- 화면 솔버 패널에서 씨앗·개체 수·다듬기 수를 고르는 입력.
- 해가 여럿인 판: 지금은 처음 찾은 해 하나로 끝난다(유일해 여부는 알 수 없음).
